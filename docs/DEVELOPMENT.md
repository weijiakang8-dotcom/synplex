# 开发与验证

## 依赖与入口

Node 26；`npm ci --ignore-scripts` 按锁文件安装。自有 Python 引擎依赖与迁移随 `vendor/agenthub/backend` 提供。所有运行数据使用独立目录，不复用正在工作的宿主环境。

`npm run open:workspace` 启动实际工作台。根 `server.mjs` 和 `seed.mjs` 保留早期界面回归资产，不是产品启动入口，`npm start` 指向当前工作台。

## 质量门禁

```sh
npm run check
npm run test:browser:core
```

第一条核验语法、模块符号、复杂度、接口、权限、真实 SQLite/HTTP、文件指纹和故障状态。第二条复用确定性核心流程，覆盖导入、回答、丢回复核对、明确执行及成果查看。运行时模型访问由 `scripts/testing/offline.mjs` 禁止。

macOS CI 保留操作系统相关检查；Linux 检查验证可部署工作台的接口与数据流，不以它替代 Mac 沙箱或输入法验收。浏览器驱动按锁定版本安装，CI 证据仅含合成数据。

## 新功能和修复

保持页面名称与真实职责一致。模型资料不能授权操作；未知用量不能填零；执行终态不能替代人工验收；修订追加而不覆盖历史。对每次修改选择最少、必要的回归，不新增付费调用来获得绿色检查。

使用已有主链断言覆盖正常、关键异常与恢复，避免测试数量堆叠。静态复杂度预算在 `scripts/quality/complexity-budget.json`，不为通过门禁随意抬高阈值。

## 发行与复现

源码包含配置模板、测试和构建定义。`.runtime`、数据库、密钥、环境、日志、缓存、下载依赖和生成发行包不提交。带依赖发行包只能在相同平台/芯片使用；源码克隆需按锁文件重新安装。

记录问题时附具体提交、平台、复现步骤、脱敏问题编号和预期，不提交真实业务原件。完整付费模型验收与收益评估另按相同材料、验收条件和完整成本进行。
