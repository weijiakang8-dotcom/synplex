# 账号与独立工作台

注册时设置登录名、邮箱、邮件验证码和至少8位密码；登录可使用登录名或邮箱。登录名为3到32位，以字母开头，可用字母、数字、下划线或短横线，不区分大小写。验证码5分钟内有效，60秒后可重发，输错5次后需要重新获取。普通用户不需要寻找连接码。

每个邮箱只能注册一个账号；邮箱忽略大小写和首尾空格，登录名只是可更改的登录方式，不决定资料归属。每个账号拥有独立项目、资料、记录、对话、成果与个人模型连接。站点维护者提供的默认模型可供已登录账号使用，个人连接仍严格隔离；默认模型密钥不会向用户公开。执行服务沿用AgentHub组织、用户和工作流隔离，审批、原提交身份、失败记录与人工验收继续保留。

## 初次配置发件邮箱

网站维护者需准备自己的SMTP邮件服务或Resend账号。SMTP使用465加密连接，或587/2525加密升级；不支持不加密的公网投递。Resend需先验证发件域名。系统不会读取其他应用的邮件密钥。

在服务器或本机终端运行：

```sh
python3 scripts/runtime/configure-email.py /absolute/path/to/workspace-data
```

按提示填写发件方式、发件邮箱、服务器和邮件授权码，或者Resend访问密钥。密码输入不显示；设置仅保存在资料目录的私有`account-mail.json`，不提交Git。不必重启，回到注册页面刷新后获取验证码即可。SMTP还需Python 3；Resend发送直接使用Node自带网络能力。

更正已有设置时，在同一命令中加`--replace`；工具会先保存仅本人可读的原设置副本，再原子替换，不删除原配置、不发信。Resend的发件地址需属于已验证域名，QQ等个人邮箱可用作收件地址；发件密钥必须复制后台完整的`re_`开头内容，不能填写密钥名称。保存只说明本机设置写入成功，不代表服务商已验收密钥或邮件已送达。

验证码不会通过网页、接口响应、日志或开发者入口返回。发件服务未配置时明确暂停注册，已有账号仍可登录。完成配置后需用真实收件箱验收一次，测试邮件夹具不能证明真实送达。

## 保留原工作台

升级不会把原资料交给第一个注册者。从这台电脑原来的私人启动入口进入后，点击“绑定邮箱”，注册时明确勾选“带入这台电脑的已有项目”，才会绑定原主人的项目与模型连接。普通访客看不到这个选项。每份原工作台只能绑定一个账号。原件、任务身份和历史都不重建。

私人启动文件保留作本机原主人入口，不是访客的注册方式；不要把它或扩展连接包分享给其他人。

## 登录保持与退出

网页登录有效期7天。正常刷新和服务重启后会话保留；退出立即撤销当前会话，并通知同浏览器的其他标签页重新登录。浏览器中的未提交草稿按账号隔离保留，换账号不会显示他人的草稿。

扩展仍使用当前项目专属连接；退出网页不等于撤销已经下载的扩展凭据。连接包具有访问权限，只交给自己使用的宿主。当前不包含团队邀请和管理员用户管理页面。

## 运维边界

账号、验证码的保护资料、加密模型、项目连接与执行环境均属私有数据。备份要包含整个资料目录以及独立执行环境；恢复默认停用执行，核对原任务后再启用。账号数据纳入工作台指纹与恢复核对。多租户执行身份需新版执行适配；不能把新增账号资料直接交给不理解账号隔离的旧程序。回退使用完整的升级前联合备份，保留升级后产生的资料，不能只改启动路径绕过兼容性检查。

公开部署仍需HTTPS与正确的反向代理配置。当前发送与登录限流只信任实际连接地址；通过本机代理时采用共享限流，不信任浏览器伪造的转发头。

## 设置登录名与找回密码

已有账号进入工作台后，点击侧栏底部的“账号设置”，填写并保存登录名；重名时会提示换一个。修改后，新登录名或原邮箱都可登录，旧登录名不再可用，项目与当前登录状态保留。

忘记密码时，在登录页点击“忘记密码？”，填写注册邮箱、获取验证码、设置并确认新密码，再点击“保存新密码”。验证码5分钟内有效，最多尝试5次，60秒后可重发；注册验证码不能用于重置密码。页面统一提示“如果该邮箱已注册”，不公开邮箱是否存在。

重置成功会撤销该账号所有网页登录会话，需要用新密码重新登录。账号、项目、对话、模型连接与成果保留，其他账号不受影响。已下载的项目扩展凭据不属于网页登录会话，若怀疑泄露应另行撤销，不应以修改密码代替处理。密码重置记录、登录名和待消费验证码纳入完整备份与版本兼容性检查；不要将新数据交给不理解这些规则的旧程序。


## 三个独立账号入口

- `/login`：使用已有登录名或邮箱和密码登录。
- `/register`：首次创建账号，获取的是“注册验证码”。
- `/forgot-password`：已有账号忘记密码时使用，获取的是“重置验证码”。没有账号请点击“还没有账号？先注册”。

三个页面各有独立地址、标题与按钮，刷新或浏览器前进后退不会切换到另一种用途。旧 `/app?account=register`、`/app?account=reset` 链接仍可用，打开后会显示对应的新地址；未登录访问工作台会显示 `/login`。验证码接口及用途隔离不变，未注册邮箱的找回请求不实际发送邮件，也不会暴露该邮箱是否已注册。

## 本机与线上历史衔接

同一邮箱在不同安装环境中，仍分别使用各自数据库；系统不会仅凭邮箱声明读取另一台电脑。需要携带已有历史时，由维护者核对两端邮箱身份，离线追加迁移已结束的项目。线上原账号、密码、登录名、已有项目和资料保留，不把账号换绑为私人根身份。

维护者使用 `scripts/runtime/history-transfer.mjs`：先 `export 源资料目录 邮箱 私有导出文件`，在目标正常停机并完成联合备份后，运行 `import 目标资料目录 私有导出文件`。`export-legacy` 仅用于维护者已核对的原私人工作台，要求原连接凭据仍有效；不是注册用户可调用的接口。导出不含密码、登录凭据或模型密钥，传输仍需加密保密。

迁移保留原件指纹、决定、对话、成果与费用记录；旧执行标记为历史归档，不重新提交任务。相同迁移文件可安全核对回执，不重复新增；内容冲突或未决执行时停止，保留两端数据。模型配置单独由维护者处理，不随普通历史文件迁移。升级后的归档数据不能直接交给不理解该格式的旧程序，回退使用完整升级前备份。
